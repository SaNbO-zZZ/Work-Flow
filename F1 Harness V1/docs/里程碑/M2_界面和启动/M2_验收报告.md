## 做了什么
- **桌面 App**：`~/Desktop/F1 Harness.app`，法拉利 F1 车队盾形图标（仅本机自用），不占 Dock。C 语言启动器负责：检查是否已在运行 → 等硬盘（开机时最多等 2 分钟）→ 检查能否读硬盘（读不了就引导开"完全磁盘访问权限"）→ 挂载 Hermes 映像 → 拉起服务 → 打开网页。
- **网页服务**：FastAPI，界面照已确认的样稿。聊天逐字显示；输入框的模型和推理强度只对当前这条消息生效；`/` 命令；状态栏；关卡审核卡（通过 / 打回到指定阶段）；G1、G3 独立窗口；用量页（24 小时曲线和每小时明细，今天 / 本周 / 本月）；设置浮层（模型分工表、价格来源）。
- **总控**：能正常对话；说"做一期 XX"会立项（分配期号、建文件夹、进入排队）；也能暂停、继续、插队、取消。
- **通知**：网页开着时用网页通知（点一下跳到对应会话），网页没开时用 macOS 系统通知。
- **调度器已接入服务**：M3–M5 的步骤还没实现，所以立项后会在第一个步骤暂停，并在聊天里说明原因。

## 和计划不同之处
- 网页前端改用原生 JavaScript，没有用 HTMX；同样不需要编译打包、不用 npm。
- 聊天没有用 `codex exec`，而是用 Codex 的 app-server：它支持逐字输出，而且每一轮都能单独指定模型和推理强度，正好对应"只对当前这条消息生效"。

## 验收中的修改（2026-09-29）
### 1. 桌面图标显示不对
- 用户反馈：桌面快捷方式没有显示法拉利盾形车标。
- 排查结果：App 里的图标文件是对的，系统接口取出来的也是盾形车标加白色圆角底。问题出在 Finder 和 Dock 还在用旧的图标缓存（App 重建过一次）。
- 处理：刷新 App 登记，清掉 Dock 图标缓存，重启图标服务、Finder 和 Dock。

### 2. 模型选择规则
- 用户要求：换了模型以后不要自动回到 gpt-6-astra 高，除非自己手动改；只有立项之后，项目会话才自动回到 astra。
- 新规则：
  - 闲聊会话：一直保留手动选择，提示"会一直用这个，直到你手动改"。
  - 立项那一刻：回到 gpt-6-astra 高。
  - 项目会话：换模型只对这一条消息生效，提示"只对这条消息生效，发送后回到 gpt-6-astra · 高"。
- 复测（离屏浏览器实际操作，不发消息）：

| 操作 | 下拉框结果 |
|---|---|
| 闲聊 A 改成 sol · 低 | sol · 低，提示"会一直用这个" |
| 切到闲聊 B | astra · 高（各会话分开记） |
| 切回 A | sol · 低 |
| 刷新页面后的 A | sol · 低 |
| A 立项 | astra · 高，A 记住的选择被清除 |
| 项目会话改成 sol | 提示"只对这条消息生效" |

- 顺带修复：浏览器会缓存旧的界面脚本，导致改动后刷新不生效。现在界面文件每次都会向服务确认版本。
### 3. 改名为 F1 Harness，网页加车标
- 用户要求：这是 F1 harness，网页左上角和桌面 App 名称要改；网页左上角也要显示盾形车标。
- 用户确认：改名前桌面图标已正常显示。
- 处理：
  - 桌面 App 改为 `~/Desktop/F1 Harness.app`，开机自启已指向新 App。
  - 网页左上角、浏览器标签页标题、G1/G3 审核窗口、系统通知、启动器提示框，统一显示"F1 Harness"。
  - 网页左上角和浏览器标签页图标，改用 App 同款车标（盾形车标 + 圆角白底）。
- 未改动（避免牵动已有数据和权限）：硬盘文件夹"F1 Hermes V1"、映像 HermesCore、程序包名 hermes、App 标识 com.f1hermes.v1。
- 注意：App 重建后签名变了。如果系统提示需要"完全磁盘访问权限"，请在设置里打开 F1 Harness。
